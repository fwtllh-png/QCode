# QCode 模型配置重构：统一 OpenAI-Compatible 显式连接

## 目标与决策（按推荐方案执行）

1. **彻底删除内置 provider 目录**：删除 `internal/adapter/model/catalog.v1.json` 与 `DefaultCatalog()`，运行时所有模型路由一律来自用户配置的连接（Base URL + Protocol + Model ID + API Key 四要素）；TOML/CLI 路径同样要求显式 base_url。
2. **存量无感迁移**：加载旧 `selection.json` 时，把预设连接（openai/deepseek/glm，BaseURL 为空）用一次性冻结迁移表物化成显式连接（补 BaseURL/Protocol/模型元数据），保留原连接 ID（session profile、agent preset 引用不断裂），keyring 凭证继续可用，物化后按新 canonical 规则回写。
3. **删除 GLM/DeepSeek 专属分支**：`openai/adapter.go` 中按 provider ID 匹配的 `tool_stream`、GLM 业务错误码表、DeepSeek 请求头偏好一并移除，统一纯 OpenAI-Compatible 行为，对应字节级回归测试同步更新。
4. **模型选择沿用 composer 选择器**：已支持跨连接（不同 Base URL）选择 + "新增模型…"入口；把 Settings 模型页的 Session model 下拉从"当前 provider 内"改为跨全部已配置连接。

已确认的关键事实：TOML schema 目前无 `execution.base_url`；GLM hack 在 `internal/adapter/provider/openai/adapter.go:49`；web 预设面在 `internal/host/web/setup.go`（`webSetupCatalog`/allow-list/`setupProviderAliases`）；持久化 `webSetupConnection` 已含 BaseURL/Protocol/Metadata 字段，物化迁移不需要版本号变更（v3 字段足够）。

## Phase 1 — 运行时：显式连接路由

### 1.1 `internal/adapter/model`
- 删除 `catalog.v1.json`、`//go:embed`、`DefaultCatalog()`（catalog.go）；保留 `Catalog/NewCatalog/Provider/Model/Resolver/ReadyRoute` 类型与通用校验（`validateProvider` 保留，仅去掉 bundled 加载路径）。
- 删除依赖 bundled 结构的测试（golden_test、observation_test 中目录断言部分），`route_test.go`/`routeset_test.go` 改为内联 `model.NewCatalog` 构造。

### 1.2 `internal/runtime/app/wire`
- `route.go` `resolveExecRoute`：删除 `BaseURL=="" → DefaultCatalog` 分支；Base URL 成为必填（错误信息更新）；删除 bundled adapter 查询（统一 `AdapterOpenAICompatible`）；显式 model metadata 仍必填。
- 新增"连接目录"组装：由 active 连接 + `ExtraConnections` 统一构建一个 `model.Catalog`（每条连接 → `model.Provider{ID: 连接ID, Adapter: openai_compatible, Endpoint, Protocol, Credential, Models}`），`routeset.go` 的 plan/vision/summary/judge slot 改为对该目录解析（引用未配置 provider 的 slot 报明确错误）；`extraConnectionRoutes` 从同一目录派生。
- `model_catalog.go`：删除 bundled provider"unavailable/Add a connection"列示，目录只含已配置连接（registered/connection_baseline 来源保留）。
- `model_probe.go`/`live_models.go`：去掉 DefaultCatalog 依赖，live `/models` 列表只面向显式端点。
- wire 包全部测试改内联 catalog fixture（含 `extra_connections_test.go`、`reasoning_effort_test.go`、`model_catalog_test.go` 等）。

### 1.3 `internal/config`
- schema 增加 `execution.base_url`（TOML/CLI 路径与 provider/model/protocol 配套必填），更新 `defaults.go`、`validate.go`、route slot 校验与相关测试（`route_test.go`、`config_trust_test.go`）。

### 1.4 `internal/adapter/provider/openai`
- 删除 `policy.ToolStream = providerID=="glm"`（adapter.go:49）、GLM `structuredHTTPFailure` 错误码表（:220-243）、`X-Deepseek-Request-Id` 头偏好（:215）；更新对应 chat/字节对比回归测试与 golden。

### 1.5 构建脚本
- 删除 `scripts/catalogcheck` 与 Makefile 的 `catalog-check` 目标及其引用（verify 链路同步）。

## Phase 2 — Web host：统一连接配置与迁移

### 2.1 `internal/host/web/setup.go`
- 删除 `webSetupCatalog` 预设列示、`setupProviderAliases`、`customProviderID` 双分支与 openai/deepseek/glm allow-list（:280-282）；`resolveWebSetupConnection`/`resolveSetupProbeConnection` 收敛为单一路径：**Base URL（HTTPS 或 loopback）、Protocol（openai_chat|openai_responses）、Model ID、API Key 四项必填** + 模型元数据（探测或手填）。
- 连接 ID 继续用 `openai-compatible:<sha256(baseURL)[:6]>`；新连接必填 API Key（本地无钥端点需填占位值，按用户规格不做豁免）。
- 加载迁移：`loadWebSetupSelection` 中对 `BaseURL==""` 的旧预设连接，用冻结迁移表（从现 catalog.v1.json 抽取 openai/deepseek/glm 三家的 endpoint/protocol/模型元数据，存为 `internal/host/web` 内的 legacy JSON，仅迁移用）物化，保留原 ID，MetadataProvenance 标注迁移来源；物化后按新 canonical 校验并原子回写。

### 2.2 `launcher.go` / `workspace_manager.go`
- 删除预设分支：活动连接的 runtime overrides 恒为显式（BaseURL/Protocol/keyring 凭证/metadata）；`AddConnection/AddModel` 校验走 2.1 的统一路径；`Reconfigure`/`replaceSelectionStaged` 逻辑不变。

### 2.3 契约与生成
- `internal/host/runtimeapi/web`：删除 `SetupCatalog`/`SetupProvider` 类型与 bootstrap 的 `setup_catalog`；`SetupRequest`/`ConnectionOptions.Add` 去掉 provider/known-models 字段（保留 base_url/protocol/model/api_key/model_metadata）；`provider/list` 仅返回已配置连接。
- `make web-protocol` 重新生成三件套（contract.json / web-host.generated.ts / unary_routes.generated.go），`make web-protocol-check` 通过。
- 更新 runtimeapi 与 host/web 的 Go 测试（setup_test、setup_probe_test、launcher_test、server_test 等全部改显式连接 fixture）。

## 风险与已知取舍

- 迁移后的原 openai 连接从 `AdapterOpenAI` 变为 `AdapterOpenAICompatible`（stateless projection 等），即"统一"本身的含义；GLM 端点不再发送 `tool_stream:true`。
- 约 40 个 Go 测试文件需改为内联模型元数据 fixture，机械但面广；分阶段提交（Phase 1→2→3→4），每阶段独立可测。
- API Key 按规格对新建连接必填；keyless 本地端点需填占位值（如需豁免可后续加开关）。
